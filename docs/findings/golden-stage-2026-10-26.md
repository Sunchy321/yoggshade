## Fixes and implementation path

- `packages/renderer/src/plan.ts` maps each base hand slot to the same-type GOLDEN slot and keeps CARDTYPE validation. `packages/renderer/src/render.ts` evaluates the premium reflection shader; `render-card.ts` accepts a finite `goldenReflectionTimeX` override for phase measurement.
- T09 elite bug: `Actor.IsElite()` reads the entity's ELITE tag (`Actor.cs:1349-1367`), and `Actor.UpdateEliteComponent()` enables elite renderers only when `IsElite()` is true (`Actor.cs:5141-5148`). The offline plan matched only ordinary prefab names, so the default-active premium spell node `InHand_Ability_Unique_Dragon_Premium` was omitted from gating and leaked onto non-ELITE TIME_EVENT_999. The premium spell and hero node names from `assets/frames/hand-spell-golden/frame_recon.json` and `assets/frames/hand-hero-golden/frame_recon.json` are now included in the same tag-driven gate.
- JAIL_321 white arc and missing PREPARE flag: `Actor.UpdateEliteComponent()` calls `RenderUtils.EnableRenderers(m_eliteObject, enable, includeInactive: true)` (`Actor.cs:5141-5147`), so the whole elite subtree must follow `TAG_ELITE`. In `assets/frames/hand-minion-golden/frame_recon.json`, `m_eliteObject` points to `Unique_Ally_Dragon`, which contains `Unique_Ally_Dragon_Shadow` with a renderer sampling `GenFX_Card_InHand_Premium_BannerAtlas`; the plan had hidden only the parent by node name, leaving this child visible for non-ELITE JAIL_321. The child is now included in the same tag gate. The same probe showed `PrepareableBannerContainer` had no children in every premium frame, while the normal frame packs had the extracted nested prefab. `Actor.UpdateCardColor()` activates the prepare container and instantiates `DeckActionBanner` when the PREPARE flag is set (`Actor.cs:6418-6445`); `scripts/extract_banner_assets.py` now resolves and merges nested banner prefabs for the five GOLDEN frame slots as well. JAIL_321's `PREPARE=4354` now produces `Prepareable_Banner_mesh`.
- JAIL_450 DK weapon outer frame: `Actor.SetMaterialWithTexture()` writes the class atlas to `portraitMesh[m_portraitFrameMatIdx]` only for SPELL/BG_SPELL or a single-color DEATHKNIGHT weapon (`Actor.cs:6662-6708`, branch at `:6700-6708`). The GOLDEN plan previously suppressed every class-atlas write under `goldenActive`, so the independent `PortraitFrame_mesh` stayed generic. It now writes the DK weapon atlas to that one frame slot while leaving the premium card-face material intact. UnityPy `assets/frames/hand-weapon-golden/prefab_report.json` confirms `m_portraitFrameMatIdx=0` and `m_portraitMatIdx=1`; `data/tables.json` maps DK weapon color type 1 to `Card_Inhand_Weapon_DK_91041c28.png`.
- JAIL_450 GOLDEN weapon flowers: the user clarified that the decorative flowers must remain gold. Replacing the shared slot with the DK atlas darkens both flowers; replacing it with the generic GOLDEN atlas loses the DK frame. The renderer still binds one atlas to `PortraitFrame_mesh` slot 0, so `scripts/compose_golden_dk_weapon_atlas.py` copies only the two flower UV rectangles from `Card_Inhand_Weapon_Premium.png` into `Card_Inhand_Weapon_DK_91041c28.png`; `scripts/extract_frame.py --slot hand-weapon-golden` generates the composite after extracting the premium frame. UV attribution uses `PortraitFrame_mesh` submesh 0 (`root.3.4.0`, 1,358 triangles), mapped from the user-visible JAIL_450 flower ROIs; A/B: `explore/2026-10-26-golden-stage-b/output/dk-weapon-flower-uv-patch-probe/JAIL_450-gold-flowers-dark-DK-frame.png`.
- `scripts/extract_frame.py` extracts the five premium frame assets. `scripts/extract_golden_portrait.py` resolves CardDef materials/animation, evaluates the frozen UberShader phase, and composes the Metal layer variant. The output portraits are ignored generated assets in `assets/portraits/`.
